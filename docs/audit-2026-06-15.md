#### ROOT CAUSE CONFIRMED (source-code read-through, [matches/page.tsx:116](app/(dashboard)/matches/page.tsx#L116), [player-card/page.tsx:116](app/(dashboard)/player-card/page.tsx#L116), [usage.ts:41](lib/db/usage.ts#L41), [upload/page.tsx](app/(dashboard)/upload/page.tsx))
- `/upload`'s "Footage type" radio includes **"Opponent footage"** as a standalone option, available with no tournament/opponent context. Selecting it sets `videos.sourceType = 'opponent'` ([upload/page.tsx](app/(dashboard)/upload/page.tsx), `SourceType` includes `'opponent'`).
- Both `/matches` ([matches/page.tsx:116](app/(dashboard)/matches/page.tsx#L116)) and `/player-card` ([player-card/page.tsx:116](app/(dashboard)/player-card/page.tsx#L116)) run the **identical filter**: `.where(and(matchFilter, or(isNull(videos.sourceType), ne(videos.sourceType, 'opponent'))))` — i.e. **explicitly exclude any match whose video has `sourceType = 'opponent'`**, with the in-code rationale "Scouted opponent footage lives under Tournaments → Opponents, not here."
- That rationale only holds if the match is linked via `matches.tournamentOpponentId` to a `tournament_opponents` row (which IS how `/tournaments/[id]/opponents` finds opponent footage — [player-card/page.tsx:160-162](app/(dashboard)/player-card/page.tsx#L160)). But a standalone `/upload` with "Opponent footage" selected **never sets `tournamentOpponentId`** — that linkage only happens via the `tournaments/[id]/opponents` flow ([opponents/actions.ts](app/(dashboard)/tournaments/[id]/opponents/actions.ts)).
- `/usage`'s `getUserUsageStats` ([usage.ts:30-41](lib/db/usage.ts#L30)) counts `matches` by `userId` + `status='analysed'` **only** — no `sourceType` filter at all. So it correctly counts these 3 matches.
- **Net effect: a user who uploads footage via `/upload` → "Opponent footage" (without first creating a Tournament + Opponent) gets a fully analysed match that consumes their quota and AI cost, but becomes permanently invisible** — not in `/matches` (excluded by `sourceType='opponent'`), not in `/tournaments/*/opponents` (no `tournamentOpponentId`), only visible as a number on `/usage`. This is very likely what happened to this account's 3 analysed matches (3h46m).
- **Corroborating evidence from `jobs/generate-training-plan.ts:36-49`**: the training-plan generator's own "gather user match data" step uses the *exact same* filter (`eq(matches.status, 'analysed')` + `inArray(videos.sourceType, ['own_competition','own_sparring'])`). If it returns zero rows, the function skips the "ATHLETE DATA" section entirely and falls back to opponent-intel-only content (`gather-opponent-data`, lines 122-140 — scouted opponents from `tournamentOpponents`/`tournaments` with `eventDate > now()`). The fact that this account's Player Card Training Plan widget shows **opponent-only content (Nihate Pahati, AJP 10W/2L)** with no "your win rate / control rate" section is consistent with `userData === null` here too — i.e. the same 3 matches are invisible to the training-plan generator for the identical reason. (Separately, see the `/tournaments` section below: the "Nihate Pahati" tournament that fed this plan doesn't appear in the current `/tournaments` list, suggesting the cached plan itself may also be stale — a second, smaller "stats don't match each other" issue worth a quick check once the main bug is fixed.)
- **Recommended fix (pick one, both are reasonable):**
  1. **Remove "Opponent footage" as a `/upload`-page footage type entirely** — opponent uploads should only happen via Tournament → Opponents (where `tournamentOpponentId` gets set correctly), OR
  2. **If a standalone "Opponent footage" upload is kept**, either (a) prompt the user to pick/create a Tournament+Opponent at upload time so `tournamentOpponentId` is set, or (b) give these orphaned matches a home in the UI — e.g. a "Scouted footage" section on `/matches` (the `SOURCE_LABEL` map already has `opponent: 'Scout'` defined but unused due to the exclusion filter, suggesting this may have been the original intent before the filter was added).
- Visual (secondary): single "Analysing…" card with spinner-style state, "+ Upload another match" CTA — fine in isolation.

**Overall**: the underlying data pipeline (positions, attacks, win probabilities, control %) is genuinely rich and correctly computed — but **4 of these 5 files render that data as small text rows** (`text-xs`/`text-[9px]` labels and numbers at equal visual weight), not as the "stats-forward" visuals the brand needs.

This is genuinely close to Hudl/Strava quality and should be the **template** for the other pages — right now it's the only place this visual language exists.
- **Fight View (`fight-view.tsx`, 641 lines)**: career W/L records (e.g. "10W-2L") render as `text-xs`/`text-[9px]` inline spans — the single most scannable "is this opponent dangerous" number gets the same visual weight as a label. "Key attacks" (e.g. "Armbar ×3") are plain text. The one good element, `GameStyleBar` (top-control % as a horizontal bar), is underused.
- **Fight Card (`fight-card/[opponentId]/page.tsx`, 700 lines)**: the **best visual moment in the audit** — large `text-5xl/6xl` VS hero with blue/rose side-accents and a shareable card (`ShareButton`, "Powered by RollPlan.AI" footer). But below the hero, "Dominates from" / "Attacks" stats render as raw seconds (e.g. "87s") with no "% of match" context — a horizontal position-time bar comparing both athletes would be far more "WOW."
- **Branding gap**: across all 5 files, the brand's gold (`#F5C518`) **does not appear once**. Instead there's an unplanned mix of blue / rose / amber / violet (a 4th accent color used only in the Scouting View's "Ask AI" tab) — reads as generic "sports app," not RollPlan's blue/gold identity.
- **Concrete bugs found**:
  - `fight-card/[opponentId]/page.tsx`: `StatRow`'s `accent?: 'emerald' | 'rose'` prop has branches for both colors but **no caller ever passes it** — dead conditional code (lines 673-700).
  - `fight-card/[opponentId]/page.tsx`: a locally-redefined `POSITION_LABEL` map includes `rear_naked: 'RNC'` — `rear_naked` isn't a real position in `lib/taxonomy/positions.ts` (it's a submission, not a position), so this map entry is dead/incorrect.
  - `matches/[matchId]/page.tsx`: `totalMatchTime` (line 128) is computed but **never passed to `ScoutingView`** — dead computation, possibly a leftover from a removed stat.
  - `scouting-view.tsx`: the `PredictionTab`'s "Upload my footage" CTA shows unconditionally in scouting mode, even for users who already have footage uploaded (`ownTotal > 0`) — no gate against existing own-match data.
  - `fight-view.tsx`: `PrivateBadge` shown next to "Their game" but not next to "Gameplan" — inconsistent privacy-indicator placement between two columns meant to mirror each other.
- **Biggest opportunity**: take the `StatArcGauge` / Arsenal-vs-Exposed pattern from the Scouting View's Stats tab and push it "up the funnel" into Fight View and Fight Card — replace the text-row career records and "Dominates from … 87s" rows with the same gauge/bar visual language, anchored in brand gold for the win-probability/favourable-matchup signal.

# Synthesis — Prioritized Roadmap to "WOW"

## TL;DR
RollPlan's underlying engine is genuinely strong — 639-entry technique KB, AI scouting pipelines, position/attack extraction, training-plan generation, Fight Card data layer — far more sophisticated than most apps at this stage. The "WOW" gap is **not** "build more features." It's three things, in order:

1. **Two data-integrity bugs are hiding the product's own output from its users** (account fragmentation + the `sourceType='opponent'` exclusion). Until these are fixed, "Stats are really bad" will remain literally true for this account regardless of any visual redesign.
2. **The one place stats look great (Scouting View → Stats tab) hasn't been used as the template anywhere else** — Fight View, Fight Card, Player Card, and the marketing site all render the same underlying numbers as small text rows instead of the gauges/bars that already exist in the codebase.
3. **The marketing site doesn't look like the app** — blue/gold rebrand reached the in-app CTA but not the homepage, which is still a monochrome, text-heavy "generic SaaS" page with huge dead desktop margins and zero social proof.

## P0 — Fix before anything else (data integrity, ~1-2 days)

1. **🔴🔴🔴 Account fragmentation** ([finding](#-new-p0--account-fragmentation-this-user-appears-to-have-at-least-4-separate-users-rows)) — 4 `users` rows likely belong to one person, split across `fandi.yacine@gmail.com` (×2) and `yacine.fandi@gmail.com` (×2). 3. **🔴 `.app` vs `.ai` email domain** ([finding](#-critical-cross-cutting-bug-stale-app-domain-emails)) — 5 occurrences across `app/about/page.tsx` (3) and `app/faq/page.tsx` (2). **Why this order matters**: #1 and #2 are the actual reason every stats surface in this audit looked broken or empty. Recommend fixing #1/#2 first, then **re-running this audit's screenshots** for `/player-card`, `/matches`, `/tournaments`, and the Fight Card/Scouting pages — they may already look dramatically better with zero design changes.
